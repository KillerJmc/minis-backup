## 2026-11-25 minis-git-backup v2.0.0 上线 + 并行测试实测无效

- **v2.0.0 已发布**：技能仓库 `6345e17`，工程仓库 `e599890`，产物 `minis-git-backup_v2.0.0.zip`（8 文件 35 KB），v1.1.0 已归档；三处（工作副本 / `/var/minis/skills/` / 外部镜像）`SKILL.md` 与 `backup.py` md5 一致。
- 核心变更：`.git` / 子目录 `.gitignore` 临时改名 `.git-backup` / `.gitignore-backup` 让 git 当普通文件跟踪；回验改为**以本地为基准**（远程缺文件、内容不同 → 失败；远程多出 → 只提示）；新增 `BACKUP_GIT_NO_NETWORK=1`。
- **测速结论（重要，别再试）**：15 项全量 —— 1 线程 **374s**、2 线程 590s、5 线程 736s。iSH 是 aarch64 模拟层且用例 I/O 密集（每例复制 1100+ 文件再让 git deflate 上千对象），线程越多越慢。`--jobs` 开关保留但默认 1。
- **沙箱必须真实复制**：早先硬链接派生让所有沙箱共享 inode，用例的原地写（脱敏改写、git 追加 `logs/HEAD`、append 文件）穿透污染主副本，导致「没有可提交的改动」「内层仓库没进备份」等假失败，且**单例跑通过、全量跑失败**。整份仅 3 MB / 1100 文件，复制比排错便宜。
- `purge_stale` 的 `mgb-` 前缀会误删主副本 `mgb-master-*`，已加跳过。
- **排查方法教训**：每改一处就跑全量（6min/次）是浪费；正确做法是只跑单例、保留沙箱、一次取全 `git status` 原文（用 `repr()` 看空白）。
