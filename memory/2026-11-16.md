## 新技能 quota-minekuai v1.0.0（麦块云额度 + 签到 + 纯 HTTP 登录）
- 站点 `https://minekuai.cn`（麦块云；注意 `minekuai.com` 是「麦块联机」游戏服，独立品牌）。
- **业务 API 在根域 `/app/*`**：`minekuai.cn/app/*` 通；`minekuai.cn/api/app/*` 返回 SPA HTML；`api.minekuai.cn/app/*` 一律 401。Minis 供应商配的 base URL 走的是 `/v1` 推理 API，与业务 API 两套。
- 认证：`Authorization: Bearer <JWT>` + `clientid: 4******************************1`（前端写死）。JWT 7 天有效。

## quota-modelscope v2.1.0：新增每日签到 checkin.py
- 位置：`/var/minis/skills/quota-modelscope/scripts/checkin.py`，纯 HTTP、无浏览器。
- 关键发现：魔搭**没有**签到按钮，也没有 checkin/signin 接口（`/magicubes/signin` 等全部 404）。每日发放由服务端在「当天首次带登录态访问站点」时判定，依据 `GET /openapi/v1/magicubes/earn/rules` 中 `category_key=daily` 两条规则的 `today_used`：`daily_active` 200 粒 + `aliyun_bindlogin` 50 粒，**都只有 1 天有效期**。
- 脚本流程：读规则 → `today_remain>0` 时 GET `/home` 触发 → 轮询规则 3 轮（4s 间隔）确认到账 → 已领则跳过，幂等。
- 退出码：0 完成 / 2 未到账需人工 / 3 登录失效 / 4 缺配置 / 1 网络错误。结果写入 config.json 的 `last_checkin`。
- 排查经验：刚完成重新登录、旧 cookie 被踢的瞬间，balance 接口会短暂返回 0（页面同源请求却已显示 250），等 cookie 刷新后恢复正常——不要误判成账号没额度。
- 平台任务里还有一次性 50 粒项（验证邮箱、编辑个人介绍、配置个人主页）尚未做。
