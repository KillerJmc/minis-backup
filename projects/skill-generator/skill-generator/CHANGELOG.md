发布流程（改）
- 分两轮：第一轮只把变更记录贴在对话正文并结束，确认后才提交与上线；「发布吧」不等于认可条目。
- 进入发布的时机：修改完成即停，只在用户说发布或明确问怎么发布时才发起确认；改完不等于要发布。
- 发布确认格式：变更记录条目 + 改动文件清单表格（文件名可点、类型、改动量、一句话说明、表下合计），不贴 diff 正文。

- 确认的生效条件：贴出后任何文件再变动、版本号改变、追加新要求，原确认立即作废，必须重贴重确认。
- 不给捷径：不把「重新过目」和「直接发布」并列成选项让用户选。
- 提交前回查：`git diff --numstat` 的文件数与增删行数必须与确认包一致，不一致退回第一轮。
- 发布后汇报：给出 commit hash 与 message、deploy 实际推送的文件与镜像同步结果、三处版本号，不能只说「已发布」。

撤销与回滚（新）
