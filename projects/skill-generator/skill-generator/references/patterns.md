# 好与坏

全部取自真实踩坑，左边是见过的写法，右边是改后的。

## 描述

```yaml
# 坏：长句，触发词在句尾，被截断就只剩背景
description: 让每个会话绑定到外部挂载的一个工程目录，支持改名、合并、同步技能与记忆。
```

```yaml
# 好：功能名列举
description: 项目绑定，项目迁移，项目查询，资源同步
```

## 正文首句

```markdown
# 坏：标题占位，App 描述栏显示成 "# 项目工作区"
# 项目工作区

**工程 = `<挂载>/projects/` 下的一个目录……**
```

```markdown
# 好：与 description 一致的一句话
项目绑定，项目迁移，项目查询，资源同步。
```

## 功能表

| 坏 | 为什么 |
|---|---|
| `我在哪` / `改名、合并` | 口语当功能名，概括不了行为 |
| `挂载初始化` | 内部准备步骤，用户不会这样要求 |
| `写文件规则` | 是约束，不是功能 |
| `F1 定位` | 编号增加阅读成本 |

好的写法是概括动宾：**项目绑定 / 项目迁移 / 项目查询 / 资源同步**，口语只进「触发关键字」列。

## 破坏性操作

```
坏：目标里已有同名文件且内容相同 → 跳过，然后删除源目录
    等于替用户判断"这两份一样，删掉没问题"
好：目标里已有任何同名路径 → 立刻中止，两边一个文件都不动，把冲突清单给用户
```

## 参数解析

```
坏：migrate --json  → 把工程改名成 "--json"，旧目录按迁移流程处理
好：名字以 - 开头一律非法，rc=2，什么都不动
```

## 测试期望

```
坏：测试写"内容相同应跳过，rc=0"，实现照做，测试永远绿——
    绿的是错误设计。
好：先问"跳过之后源目录怎么办"，发现会删掉用户数据，于是改期望为 rc=1 中止
```

## 规则放在哪

```
坏：GLOBAL 写"每往工程目录写文件，立刻记进 PROJECT.md"+ SKILL 也写一遍
    → 两处措辞不同，一边改了另一边忘，计数 141/156 对不上

好：GLOBAL 只写"何时调用、判据"，SKILL 写"怎么做"，
    细节只在 references 出现一次
```
