# 人工确认清单

`validate.py` 能判的 30 多条已经进代码（元数据、首句一致、功能表、references 指向、tests 存在、
变更记录格式、工程层文件、git 状态、忽略规则、部署产物纯净度）。这里只留**工具判定不了**的。

按生命周期分段，只留工具判定不了的。

## 设计期（写 SKILL.md 时）

- [ ] 功能名是概括性动宾，不是口语也不是内部步骤（`项目绑定` 而不是 `改名、合并` 或 `挂载初始化`）
- [ ] 每个功能小节写清四件事：何时用、命令、输出怎么读、出错怎么办
- [ ] 用例覆盖正常、边界、异常三类路径
- [ ] 幂等操作有重复执行用例（第二次跑同一个命令结果不变）
- [ ] 负向自检：把某条用例的期望改错，测试必须变红——否则用例是摆设

## 运行期（只有跑了才知道）

- [ ] 未知参数报错退出（`--foo` 不被当成文件名）
- [ ] 输出不依赖缩进对齐（UI 渲染后层级不丢）
- [ ] 破坏性操作有 `--dry`；冲突时整体中止，不替用户判断
- [ ] 打包失败时旧产物没被挪走
- [ ] 同一命令两次运行结果一致（幂等）

## 发布后

- [ ] 汇报四样：commit hash 与 message、deploy 推送的文件与镜像结果、产物 zip、三处版本号
