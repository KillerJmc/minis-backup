# 备份机制：从 tar.gz 打包改为 `.git` 改名跟踪

> 2026-11-24 定稿 ｜ 适用 v2.0.0 及以后 ｜ 一句话：把所有 `.git` 临时改名成 `.git-backup`，让 git 当普通文件收录，推送后立刻改回。

## 为什么放弃 tar.gz

v1.x 的方案是「找到每个含 `.git` 的目录 → 整目录打成 tar.gz → 把包名带时间戳提交进去」。它在功能上能跑通，但仓库会以每轮一个整包的速度膨胀。

为了让「内容没变就不产生新对象」，曾试过确定性打包：

| 手段 | 效果 |
|---|---|
| 遍历顺序固定（排序） | 做到 |
| 文件 `mtime=0`、`uid/gid/username` 归零 | 做到 |
| `gzip` 头 `filename=''`、`mtime=0` | 做到 |
| 内容不变连打三次 | 对象数 19 → 19 → 19，不增长 ✅ |
| 只要有文件变动 | 整包重新存一份，等于把整份历史再写一遍 ❌ |

也就是说，确定性打包只解决了「什么都没改也要重存」，解决不了「改一个字节就重存全部」。包名必须带时间戳（用户要求可读、不覆盖），所以路径每轮都是新的，连「包没变」的情形也照样新增一棵树。

结论：**包是快照，不是增量**。要真增量，只能让 git 自己按文件跟踪。

## 方案：改名绕过保留名

`.git` 是 git 的保留名，不可能被跟踪：

| 试验 | 结果 |
|---|---|
| `git add -A -f .`，子目录里有真 `.git` | `error: 'sub/' does not have a commit checked out`，整体失败 |
| `git add -f sub/.git/HEAD`（伪造的 `.git` 目录） | 静默跳过，`ls-files` 里没有该文件，`check-ignore` 也查不到 |

改名绕开这条限制：`.git` → `.git-backup` 后它就是个普通目录名，`git add -A` 正常收录。提交推送完成（无论成败）在 `finally` 里改回来，本地始终处于正常仓库状态。

实测（`/tmp` 沙箱）：

- 第一轮：26 个文件入库，远程可见 `projects/xxx/.git-backup/HEAD` 这类路径；
- 第二轮只改一个文件：`9 files changed, 7 insertions(+)` —— **只增变动文件对应的对象**，没有整包重存。

副作用是正向的：远程仓库能像普通仓库一样点开每个文件夹和文件，读到的是真实内容而不是一个二进制包。

## 必须同时改名的 `.gitignore`

只改 `.git` 会踩一个静默坑：子目录里的 `.gitignore` 会被备份仓库自己读走。`projects/skill-generator/.gitignore` 里写着 `/skill-generator/`（它原本是用来排除内层技能目录的），一旦内层仓库以 `.git-backup` 之名进来，这条规则照样生效，把整个内层仓库**静默排除**——第一版自测内层 0 个文件入库，就是这么来的。

修法：`.gitignore` 同步改名成 `.gitignore-backup`。改名后 8 个子仓库全部入库，内层各 139~209 个文件。根目录的 `.gitignore` 保留原名（它管的是备份仓库自己，必须生效）。

## 回验：方向不能反

推送成功后立刻克隆远程到 `/tmp`，把 `.git-backup` 改回名字，做三件事：

1. 子仓库能 `git log`（历史没坏）；
2. `.gitignore-backup` 能还原；
3. **以本地为基准**逐文件比对内容。

第 3 点的方向曾经写反过：拿克隆下来的内容当基准，只要远程有就算通过，本地多出来的文件被放过。结果是「本地新增了文件、远程没推上去」这种最常见的失败完全检不出来。正确方向是**本地 = 源、远程 = 副本**：

| 情况 | 判定 |
|---|---|
| 本地有、远程没有 | ❌ 失败（备份丢了内容） |
| 两边都有但内容不同 | ❌ 失败（备份不完整） |
| 远程有、本地没有 | ⚠️ 提示不阻塞（来自更早的备份，或本地删过） |

## 为什么不选别的

- **子模块**：要建 4~6 个远程仓库，每次备份推多次，维护成本远超收益。
- **`git bundle`**：只含已提交内容，工作区未提交的改动会丢——而备份的意义就是把这些也存下来。
- **`.git-archive/` 快照目录**：v1.1.0 短暂用过，还是包，还是膨胀，已删除。
- **裸推送 `.git`**：技术上不可行（见上表）。

## 边界

- 根目录自己的 `.git` **不改名**（它就是备份仓库本身），`bak/` 内的不动。
- 改名范围是挂载根下任意层级、含嵌套仓库；中断残留的 `.git-backup` 在下次执行开头由 `heal_leftover()` 改回。
- 改名期间工作区不完整（`.git` 不在原位），因此全程包在 `try/finally` 里，异常也要改回。
