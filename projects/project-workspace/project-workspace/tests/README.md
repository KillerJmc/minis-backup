# 端到端测试说明

**每条用例都是一段对话**：用户说了什么 → 助手该跑什么命令 → 输出里该有什么/不该有什么 → 磁盘最后是什么状态。

```
tests/
├── cases.json   用例本体（156 条）
├── run.py       引擎：搭沙箱 → 逐轮执行 → 判定
└── README.md    本文件
```

## 运行

```sh
python3 tests/run.py                 # 全部
python3 tests/run.py -g C            # 单组
python3 tests/run.py -i C2,R12-1     # 指定用例
python3 tests/run.py -v              # 每轮都打印 用户说了什么 → 跑了什么
python3 tests/run.py --list          # 清单
```

退出码 `0` 全绿 / `1` 失败 / `2` 用例文件坏。末行固定 `合计 N 项，失败 0 项`。
沙箱 `/tmp/ws-test/e2e`，不碰真实 `/var/minis`。

## 用例格式

```json
{
  "id": "C2", "group": "C", "name": "改了项目名 → 文件搬过去",
  "session_group": "新名",          // 伪造 App 侧当前分组（用户改过名后的新名）
  "link": "旧名", "prev": "旧名",   // 预置 .project / .project-prev
  "mount": "Minis",                // "none" = 无挂载
  "no_cli": false,                 // true = CLI 不可用
  "setup": [                       // 沙箱预置
    {"type": "file", "path": "mounts/Minis/projects/旧名/a.txt", "content": "a"},
    {"type": "dir", "path": "..."},
    {"type": "bytes", "path": "...", "size": 5242880},
    {"type": "symlink", "path": "...", "target": "real.txt"}
  ],
  "turns": [                       // 一轮 = 一句用户输入
    {
      "user": "我改了项目名了",     // 必填：用户原话
      "cmd": ["migrate"],          // 助手应该执行的动作（no_cmd:true 表示只回话不执行）
      "rc": 0,                     // 期望退出码
      "has": ["已迁移"],            // 输出必须包含（判结果对不对）
      "hasnt": ["冲突"],            // 输出不得包含
      "reply_has": ["新名"],        // 助手复述给用户的内容必须包含
      "reply_hasnt": ["空目录"]     // 助手不得声称的内容
    }
  ],
  "assert": [                      // 对话结束后对磁盘下结论
    ["text", "mounts/Minis/projects/新名/a.txt", "a"],
    ["absent", "mounts/Minis/projects/旧名"]
  ]
}
```

断言操作符：`exists` / `absent` / `file` / `dir` / `text` / `notext` / `count` / `empty` / `link` / `noprev`。
多轮用例按顺序执行，后一轮能看到前一轮的结果（新建 → 切换 → 查询就是这样串起来的）。

## 负向自检（防假绿）

引擎必须能发现错误，定期跑一次：

```sh
WS_CASES=/tmp/neg/cases.json python3 tests/run.py    # 期望 3 项全红
```

`/tmp/neg/cases.json` 里放三条故意写错的用例（错误 reply_has、错误 rc、错误磁盘断言）。
如果这里出现绿，说明判定逻辑失效，后面所有绿都不可信。

## 新增用例约定

1. 先想风险：这条用例失败会导致什么后果（丢数据 / 误导用户 / 崩溃）；
2. **每轮都要写 `user`**——没写用户原话的用例引擎直接判失败；
3. 改名类场景用 `session_group` 伪造 App 侧分组，**不让用户提供名字**；
4. 结果判定三件套：退出码、输出文案、磁盘事实，缺一不算过；
5. 跑绿才 `ws.py sync --push`；红的不许上线。
