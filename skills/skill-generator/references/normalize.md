# 技能规范的做法

把已有工程整理成规范结构。命令、退出码、报告格式看 `normalize.py --help` 与实跑输出，
这里只留工具判定不了的部分。

## 为什么先查名字再改结构

命名不对就改结构，改完还得再改名字，等于白做一遍。所以第一步只读：查工程目录名与 App 分组名、
技能目录名与 `SKILL.md` 的 `name`。

不一致时**只告诉用户该改成什么，脚本一个文件都不动**。工程改名要迁移目录，是用户的决定；
脚本替他改名，会让别的会话的绑定瞬间失效。

## 为什么等用户迁移完才开始

迁移是 `ws.py migrate` 的事，会复制目录、切换绑定。脚本自己做等于把两件事混在一起，
出错时不知道是哪一步坏掉。所以流程是：

```
脚本查名 → 不一致就停
用户改分组名 + ws.py migrate
用户回来说一声
脚本复查 → 通过了才改造工程层
```

## 改造只碰工程层

补 `PROJECT.md`、`PROGRESS.md`、`.gitignore`、`temp/`；技能目录内容一律不动——
那是内层，要改得单独授权。不删任何文件，不动 `projects/` 下的其他工程。
