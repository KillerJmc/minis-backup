# 沙盒演练任务

用这些任务验证本技能是否被严格执行。每个任务在独立目录跑，产物不进技能目录。

判定标准只有一条：**有没有真实跑过、有没有贴出输出**。计划、承诺、自评都不算。

| # | 任务 | 验收点 |
|---|---|---|
| 1 | 选择排序，Java，单文件 | `共 6 个用例，失败 0 个`；含空数组、单元素、重复值 |
| 2 | 冒泡排序，Java | 7 用例 + 500 组随机对拍 `Arrays.sort` |
| 3 | Dijkstra，Java | 7 用例；距离用 `long` 且 `INF` 取 `MAX_VALUE/4`，避免溢出 |
| 4 | Floyd，Java，带图和走法展示 | 8 用例 + 与 Dijkstra 交叉验证；路径必须用 `next` 矩阵还原 |
| 5 | 接雨水 I，Java | 8 用例 + 与暴力 O(n²) 对拍 |
| 6 | 接雨水 II，Java | 6 用例 + 200 组随机地形与逐格暴力对拍 |
| 7 | 两数之和，Java | 6 用例 + 500 组对拍；无解返回 `[-1,-1]` |
| 8 | 三数之和，Java | 6 用例 + 300 组对拍暴力去重解 |

## 每个任务都必须走完的链

```
start → read ds-help → route → read 命中技能 → plan → 基线 → 写 → 跑 → 对拍 → check → verify → stop
```

基线那一步用 `run --allow-fail`，因为它本来就该失败（文件还不存在）。

## 实际踩过的坑，作为检查项保留

| 坑 | 检查点 |
|---|---|
| Floyd 的路径用距离矩阵反推，得到「压缩路径」：`0 → 1 → 3` 但边权和 5 ≠ 4 | 路径逐边求和必须等于距离矩阵的值 |
| 三数之和的期望组数手算成 7，实际 6 | 期望值要从暴力解反推，或逐个组合核对 |
| 例子打印的是排序后的数组（算法原地排序） | 打印前先 `clone()` 原始输入 |
| `java ... \| grep -v ...` 让退出码变成 grep 的 0 | 用 `JAVA_TOOL_OPTIONS= java ... 2>/dev/null`，别接管道 |
| 新写的函数（如路径还原）没有检查就直接跑 | 新代码先有一个能让它失败的检查 |

前四条都真实发生过，第五条是形成这条清单的原因。
