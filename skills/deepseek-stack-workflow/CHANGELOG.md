1.0.0 · 2026-11-28

路由与执行（新）
- 29 份上游 `ds-*` 原文逐字节保留在 `references/`，文件名与上游同名，不改写、不合并。
- 每条用户消息先读 `references/ds-help.md` 路由，再读命中技能全文；支持 `references/` 与已安装技能两类来源，记录里标 `internal` / `external`。
- `SKILL.md` 只做壳：写清启动流程、标题格式与验收口径，不复制任何技能内容。

状态机（新）
- 九个命令：`start`、`route`、`read`、`plan`、`run`、`check`、`verify`、`stop`、`status`，另有 `report` 渲染时间线。
- 每轮独立 `turn_id` 与状态文件 `.state/turn-<id>.json`，状态迁移由脚本校验，越级一律拒绝。
- `read` 打印全文并记 md5、字节、行数；`run` 记命令、退出码、耗时与输出尾部。

审计（新）
- 审计源是 App 会话记录：每次调用回读 `minis-sessions-cli messages --tools`，逐条比对实际工具调用。
- 窗口从最后一条用户消息起算，`start` 之前的编辑也计入本轮。
- 首枪检查：`start` 必须在任何编辑之前；同会话换消息即 `rc 10`，要求重开一轮。
- 会话隔离：状态指针按 `session_id` 分文件，两个聊天互不覆盖。
- 编辑闸门：`file_write`/`file_edit` 之前必须已读完命中技能且有路径规划。
- 自动 verify：上一枪是原生工具时，下一次调用顺手审计并打印结论。
- 严格匹配：整条命令必须都是 `workflow.py` 调用，`cd`/`export`/注释除外。

验收（新）
- `check` 输出 11 项清单，代码能判的判、判不了的标人工确认。
- 有执行但无计划即判失败；计划必须贴进回复正文（由人核对，会话 API 读不到正文）。
- `stop` 依赖 `VERIFIED`，违规与缺项都过不去。

沙盒用例（新）
- 装载技能完成一个开发任务（编译运行 Floyd）。
- 与 skill-generator 并行：一轮内同时挂方法层与领域层。
- 与查额度技能并行：真跑外部脚本并记录。
