2.0.0 · 2026-11-24

备份方式（新）
- 不再打 tar.gz。备份时把所有 `.git` 临时改名成 `.git-backup`，git 就能当普通文件跟踪，推送后立刻改回。
- 远程可像浏览普通仓库一样打开每个文件夹和文件；子仓库的 objects 按对象去重，改一个文件只增该文件大小的对象，不再整包重来。
- 子目录的 `.gitignore` 同样改名成 `.gitignore-backup`：否则它的规则会作用于备份仓库，把内层嵌套仓库整个静默排除。

备份提交（新）
- 推送成功后立刻克隆远程验证：能 clone、`.git-backup` 能还原、每个子仓库都能读出历史。
- 内容按本地逐文件比对：远程缺文件或同名文件内容不同都判定推送失败，远程多出的旧文件只提示。验证不过就判定失败并给出原因。

环境变量（新）
- 新增 `BACKUP_GIT_NO_NETWORK=1`：设置后拒绝任何 https 地址的推送与还原，测试与演练只允许 `file://` 或本地路径。

备份下载（改）
- 还原时自动把 `.git-backup`、`.gitignore-backup` 改回原名，还原后子仓库可直接 `git log`、`git commit`、`git push`。

1.0.0 · 2026-11-24

备份初始化（新）
- 一条命令把挂载目录变成可推送的备份仓库：写 `.gitignore`、`git init`、建 `.`.archives/`。
- 纯本地操作：不联网、不配远程、不读环境变量，远程另用「远程配置」绑定。
- `.gitignore` 由脚本按当前目录结构生成，只排除本技能产物与含 `.git` 的目录，其余内容（含新增目录）默认全部入库。

远程配置（新）
- 设置或查看 GitHub 仓库地址，设置时顺带用 token 验证远程可达，提前暴露凭据问题。
- 地址可省略，改用 `BACKUP_GIT_REPO` 环境变量拼出 `https://github.com/<作者>/<仓库>.git`。

备份提交（新）
- 递归找出所有含 `.git` **或** `.gitignore` 的目录，**整目录打成 `.archives/<名>-<时间戳>.git.tar.gz`**：git 历史、被忽略的文件、未提交的文件、新增的文件夹一起进包。
- 把 `.gitignore` 也算作打包条件：它所在目录的忽略规则会静默过滤文件，整目录打包才能保住内容，同时该目录不再进入逐文件提交。
- 不含 `.git` 的目录（`skills/`、`skills-dist/` 等）作为普通文件直接入库，新增目录自动纳入，无需改配置。
- 提交信息按实际变动自动生成：区分「新增 skill / 新增工程 / 更新 skill / 更新工程 / memory 变更 / 其他目录」，skill 与否按目录内有无 `SKILL.md` 判断。
- 推送前先把远程克隆到临时目录比对历史：远端领先或分叉立即终止并提示先还原，只有本地领先才快进推送；绝不 force push。
- 推送成功后删除本地压缩包，`.`.`.archives/` 回到空；任何失败都保留包与提交。

隐私检查（新）
- 扫描 `memory/` 的敏感信息，命中项只报打码后的片段，不打印明文。
- 覆盖 API key、GitHub/AWS/Slack token、JWT、Bearer 令牌、私钥、32 位以上十六进制串、手机号、邮箱、密码赋值、账号名。
- 打码规则：默认只留首尾各一个字；密码与各类凭据全星号。
- 提交前自动脱敏，不询问、不中断，推送完成后列出脱敏清单；还原时不脱敏。

备份下载（新）
- 自动还原：先克隆到系统临时目录并解开全部压缩包，再把根目录现有所有条目（含 `.git`、隐藏文件）整体移入 `bak/<时间戳>/`，最后把备份铺回根目录。
- 不丢文件：原件完整保留在 `bak/` 由用户自行清理；克隆来的 `.git` 一并铺回，还原后根目录直接是可用的备份仓库。
- 每次还原独立时间戳目录，多次还原互不覆盖；临时目录用完即删。
